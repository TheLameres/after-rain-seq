# Иерархия дорожек: Track → Melodic / Drum

> Дополнение к `AGENTS.md` (план C3/C4). Дата: 2026-10-31.
> Решение: ровно два наследника у `Track`. Разновидности мелодических
> дорожек — это **профиль** внутри `MelodicTrack`, а не новые классы.

---

## 1. Иерархия

```
Track (abstract, track.py)
├── MelodicTrack (melodic_track.py)   ← профиль: pad, atmos, seq, sub, stab, arp, …
└── DrumTrack    (drum_track.py)      ← 16 lane, GM 36–51, сетка, без лада
```

**Почему два класса, а не класс на тип (как предлагал план v5.4).**
План описывал `AtmosTrack`, `Pad1Track`, `SequenceTrack` и т.д. как отдельные
классы. Практический минус: 6+ классов, каждый — отдельный файл, а различия
между ними — это 3–5 параметров (октава, gate, ритмический шаблон, читает ли
источник). Профиль внутри одного класса даёт ту же выразительность без
взрыва количества файлов и без копипасты `generate()`. Наследование остаётся
открытым для **структурно** разных дорожек — сейчас таких две: мелодическая (degree через Harmony) и drum (абсолютные
ноты, сетка). Новый профиль
добавляется строкой в реестре, новый класс — только если поведение
структурно иное.

## 2. `Track` — общая база

```python
class Track(ABC):
    name: str  # автоген: "Melodic 1", "Drum 1" — нужен для графа
    port: PortRef | None  # из routing.py; None = молчит, сессия жива
    channel: int  # 0..15, уникален внутри порта
    muted: bool
    sources: tuple[str, ...]  # имена источников, максимум 2 ("SOURCE", "SOURCE2")
    outbox: list[ChordEvent]  # публикация для наследников графа

    @abstractmethod
    def generate(self) -> None: ...

    def current(self) -> ChordEvent | None: ...

    def history(self, since_beat: float) -> list[ChordEvent]: ...
```

Всё, что общее для графа (outbox, current/history, топологическая сортировка,
защита от циклов), живёт здесь один раз.

## 3. `MelodicTrack` — мелодические профили

```python
class MelodicTrack(Track):
    profile: MelodicProfile  # см. таблицу ниже
    voicing: str = "1-3-5"  # из Voicing.VOICINGS
    inversion: int = 0  # 0..2, поворот с переносом октавы
    octave: int = 5
    gate: float = 0.9
    degrees: list[int]  # собственная прогрессия (у источников)
    # для seq/stab: паттерн нарезки (длительности, паузы, density)
```

Различия между типами мелодических дорожек — **данные, не код**:

| Профиль                    | Источник?         | Что играет                                      | Октава | Gate     | Особенности                                         |
|----------------------------|-------------------|-------------------------------------------------|--------|----------|-----------------------------------------------------|
| `pad`                      | **да** (корневой) | аккорды из `degrees` по `voicing` + `inversion` | 4–5    | 0.85–1.0 | публикует `ChordEvent`, сердце графа                |
| `atmos`                    | да                | один длинный аккорд, меняется раз в N тактов    | 4      | 1.0      | N — параметр дорожки                                |
| `sub`                      | нет (читает)      | корень аккорда источника `-12..-24`             | 1–2    | 1.0      | сдвиг по времени (план 1.4)                         |
| `stab`                     | нет (читает)      | аккорд источника, нарезанный, короткий gate     | 5      | 0.1–0.3  | может переозвучить другим войсингом (напр. `1-4-7`) |
| `seq`                      | нет (читает)      | ступени аккорда источника по паттерну с паузами | 4–6    | 0.5      | density, длительности                               |
| `arp`                      | нет (читает)      | обход аккорда источника вверх/вниз, 1/8–1/16    | 4–6    | 0.4      | направление, диапазон                               |
| `bass`                     | опционально       | корни прогрессии `degrees`, короткие            | 1–2    | 0.8      | может быть источником (не читает никого)            |
| `lead`                     | опционально       | `PWhite`-подобный дрейф в ладу                  | 5–6    | 0.6      | density, регистр                                    |
| `texture`                  | нет               | редкие одиночные ступени / кластеры             | 6+     | —        | раз в 8–16 тактов                                   |
| `cc_filter`, `cc_space`, … | нет               | **не ноты, а CC** по имени (`filter`, `reverb`) | —      | —        | рендерится в `control_change`, троттлинг 30 Hz      |

**CC-профили — частный случай `MelodicTrack`** без нот: генератор выдаёт
`{"control": "filter", "value": ..., "duration": ...}`, транспорт резолвит
имя через `cc_map`. Отдельный класс `CCTrack` не нужен: поведение
структурно то же (паттерн isobar на дорожке порта), отличие только в типе
события. Если позже CC-дорожке понадобится особое поведение (например,
привязка к плейхеду), профиль можно выделить в класс — иерархия это позволяет.

### Профиль как данные

```python
@dataclass(frozen=True)
class MelodicProfile:
    name: str  # "pad", "atmos", "seq", …
    reads_source: bool  # sub, stab, seq, arp, texture — True
    emits_chords: bool  # pad, atmos — True (публикуют ChordEvent)
    default_voicing: str
    default_octave: int
    default_gate: float
    cc_only: bool = False  # cc_filter, cc_space


PROFILES: dict[str, MelodicProfile] = {...}
```

`generate()` в `MelodicTrack` один: строит паттерн isobar по профилю +
параметрам дорожки. Ветвление — на уровне генератора паттерна, не класса.

### Источник чтения

- `reads_source=True` + `sources` пуст → дорожка молчит (стратегия B при
  удалении источника), но не падает и не теряет настройки.
- `emits_chords=True` → каждый аккорд кладёт `ChordEvent` в outbox;
  наследники видят `degrees`, `voicing`, могут срезать или переозвучить (механика из плана 1.4 без изменений).

## 4. `DrumTrack` — drum-машина

```python
class DrumTrack(Track):
    lanes: list[DrumLane]  # ровно 16, GM 36–51
    steps: int = 16  # 16/32/48/64, общая сетка на все lane
    accent_level: int = 127
    mutate: float = 0.5  # 0 = заморожено
    square: int = 1  # активный квадрат сетки (4 столбца пада)
    # sources игнорируется: drum не читает и не публикует гармонию
```

Правила из плана 4.2 без изменений: абсолютные ноты (не `degree`), смена
Root/Scale не влияет, gate one-shot, пауза = `amplitude 0`, три уровня
velocity силой нажатия пада, мутация 1–2 изменения за 8–16 секунд с
деградацией к базовому рисунку, `step_to_note()` — одна функция на проект,
`PEuclidean` с кешем.

**Drum не участвует в графе гармонии.** `sources` у `DrumTrack` заблокирован (пустой), попытка назначить источник —
отказ с сообщением на дисплее. Иначе
появляется бессмысленная связь «drum читает pad» и соблазн «pad читает drum»,
который графу не нужен.

## 5. Создание, имена, лимиты

| Операция        | Поведение                                                                                                                                |
|-----------------|------------------------------------------------------------------------------------------------------------------------------------------|
| `[+ NEW TRACK]` | `MelodicTrack(profile="pad")` с дефолтами плана 4.1 (A dorian, `1-3-5`, окт. 5, I–IV–III–I); тип/порт/профиль меняются на экране дорожки |
| Новый drum      | `DrumTrack` с пустой сеткой 16 lane                                                                                                      |
| Лимит           | 16 дорожек всего, drum-машин ≤ 2, источников ≤ 2                                                                                         |
| Удаление        | стратегия B: зависимые `MelodicTrack` с `reads_source=True` получают `sources = ()` и молчат                                             |

Имя — автогенерация по типу: "Pad 1", "Sub 2", "Drum 1". Пользовательское
переименование не требуется (имя нужно только для графа и дисплея).

## 6. Пример: пресет-шаблон «Dub Techno»

```
Pad 1      MelodicTrack(pad,    ch3, Синт B)  sources=()      # корень графа
Sub 1      MelodicTrack(sub,    ch2, Синт A)  sources=(Pad 1,)
Stab 1     MelodicTrack(stab,   ch3, Синт B)  sources=(Pad 1,), voicing="1-4-7"
Seq 1      MelodicTrack(seq,    ch4, Синт B)  sources=(Pad 1,)
Atmos 1    MelodicTrack(atmos,  ch5, Синт B)  sources=()
CC Filter  MelodicTrack(cc_filter, Синт B)    sources=()
CC Space   MelodicTrack(cc_space, Синт B)     sources=()
Drum 1     DrumTrack(ch10, Синт A)            # вне графа
```

Топологический порядок генерации: Pad 1, Atmos 1 → Sub 1, Stab 1, Seq 1.
Цикл `Pad 1 → Stab 1 → Pad 1` ловится на сборке, до первого тика.

## 7. Влияние на задачи AGENTS.md

- **C3 (граф и Session API):** типы `AtmosTrack`, `Pad1Track`, `Pad2Track`,
  `SequenceTrack`, `SubTrack`, `StabTrack` заменяются на `MelodicTrack` +
  `PROFILES`. Требования (ChordEvent, топосорт, циклы, стратегия B, лимит 16)
  — без изменений. `Pad2Track` из плана («обращение через такт») — это
  `MelodicTrack(profile="pad", inversion=1)` с переключением обращения
  паттерном, отдельный класс не нужен.
- **C4 (drum):** без изменений, только класс называется `DrumTrack` и
  наследуется от `Track`.
- **D2/D3 (UI):** `SOURCE`/`SOURCE2` показываются только у `MelodicTrack`
  с `reads_source=True`; у drum — скрыты. Смена профиля — энкодер на экране
  дорожки, пересборка генератора без остановки сессии.
