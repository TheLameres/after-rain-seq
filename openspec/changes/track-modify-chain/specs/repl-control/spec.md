# Spec Delta

## Purpose

Дополняет capability `repl-control` (baseline — change `init-current-system`):
управление цепочкой модификаций дорожки через единый фасад контроля — методы
показа/добавления/удаления этапов, REPL-команды `track chain …`,
автодополнение дорожек, действий и имён этапов, а также скриптовый фасад —
обёртки ScriptSession со стабильным контрактом данных (`data["chain"]`,
`data["stage"]`) для ветвления скриптов. Отдельной capability `scripting`
в baseline нет — скриптовые требования здесь, по прецеденту change
`add-drum-pattern-api` (там требование «Скриптовый фасад установки паттерна»
живёт в дельте `repl-control`).

## ADDED Requirements

### Requirement: Операции над цепочкой через фасад
Фасад контроля SHALL предоставлять операции над цепочкой модификаций
мелодической дорожки: показать цепочку, добавить этап в конец (имя этапа +
параметры парами «ключ=значение»), удалить этап по порядковому номеру
(нумерация с единицы). Применение SHALL быть немедленным (движок подхватывает
на следующем тике); результат — подтверждение с итоговой цепочкой либо
человекочитаемая ошибка (несуществующая дорожка, неизвестный этап,
неизвестный или некорректный параметр, индекс вне диапазона). Для
drum-дорожек операции SHALL возвращать успешный результат с явным
текстом-предупреждением: спецификация не применяется, цепочка остаётся
пустой (движок игнорирует цепочку drum-дорожек). Структурированные данные
результата — список этапов (строки-спецификации) и спецификация добавленного
этапа — SHALL быть стабильным контрактом для программных вызывающих
(скрипты); тексты сообщений контрактом не являются.

#### Scenario: Добавление этапа
- **WHEN** пользователь добавляет этап-арпеджиатор с параметрами к melodic-дорожке
- **THEN** фасад подтверждает операцию и возвращает итоговую цепочку с новым этапом

#### Scenario: Неизвестный этап
- **WHEN** пользователь добавляет этап с именем, отсутствующим в реестре этапов
- **THEN** фасад возвращает ошибку с перечнем доступных этапов, цепочка не меняется

#### Scenario: Drum-дорожка
- **WHEN** пользователь пытается изменить цепочку drum-дорожки
- **THEN** фасад подтверждает операцию с явным предупреждением, спецификация
  не применяется, цепочка остаётся пустой

### Requirement: REPL-команда track chain
REPL SHALL поддерживать команду `track chain <name> show | add <stage>
[ключ=значение ...] | remove <n>`: имена дорожек с пробелами — в кавычках;
`show` выводит этапы цепочки в порядке выполнения (или «пусто»); `add`
добавляет этап в конец; `remove` удаляет этап по номеру с единицы. Ошибка
разбора или применения выводится с кодом возврата 1 и не прерывает цикл REPL.

#### Scenario: Показ цепочки
- **WHEN** пользователь выполняет `track chain "Pad 1" show`
- **THEN** выводится список этапов в порядке выполнения либо сообщение о пустой цепочке

#### Scenario: Добавление этапа из REPL
- **WHEN** пользователь выполняет `track chain "Pad 1" add arpeggiate step=0.25 direction=up`
- **THEN** этап добавлен в конец цепочки дорожки, выводится итоговая цепочка

#### Scenario: Удаление этапа из REPL
- **WHEN** пользователь выполняет `track chain "Pad 1" remove 1`
- **THEN** первый этап цепочки удалён, выводится итоговая цепочка

#### Scenario: Ошибка параметров
- **WHEN** пользователь выполняет `track chain "Pad 1" add densify density=2`
- **THEN** выводится ошибка с кодом возврата 1, цепочка дорожки не меняется

### Requirement: Автодополнение track chain
Автодополнение SHALL подсказывать: имена дорожек после `track chain`,
действия `show|add|remove` следующим токеном, имена этапов после `add`.

#### Scenario: Подсказка этапов
- **WHEN** пользователь набирает `track chain "Pad 1" add ar<TAB>`
- **THEN** предлагается имя этапа `arpeggiate`

### Requirement: Скриптовый фасад цепочки
Скриптовый фасад SHALL предоставлять операции над цепочкой: показать цепочку
(список этапов в структурированных данных результата), добавить этап
строкой-спецификацией («имя [ключ=значение ...]»), удалить этап по
порядковому номеру (с единицы). Арность вызовов SHALL проверяться
статической валидацией скрипта до исполнения; ошибку движка при исполнении
фасад SHALL оформлять как фатальную по умолчанию. Предупреждение об
игнорировании цепочки drum-дорожки SHALL НЕ прерывать скрипт — скрипт
продолжает работу, предупреждение попадает в отчёт. Поля структурированных
данных результата (список этапов, спецификация добавленного этапа) SHALL
быть стабильным контрактом, позволяющим скрипту ветвиться (например, по
пустоте цепочки); тексты сообщений контрактом не являются.

#### Scenario: Скрипт ветвится по цепочке
- **WHEN** скрипт запрашивает цепочку дорожки с пустой цепочкой
- **THEN** данные результата содержат пустой список этапов, скрипт может
  ветвиться по его длине

#### Scenario: Скрипт добавляет этап
- **WHEN** скрипт добавляет этап строкой-спецификацией
  `"arpeggiate step=0.25 direction=up"`
- **THEN** этап добавлен в конец цепочки дорожки, данные результата содержат
  спецификацию добавленного этапа и итоговую цепочку

#### Scenario: Drum-дорожка в скрипте
- **WHEN** скрипт добавляет этап drum-дорожке
- **THEN** результат успешен с текстом-предупреждением, скрипт продолжается,
  спецификация не применена, предупреждение попадает в отчёт

#### Scenario: Неверная арность
- **WHEN** скрипт вызывает добавление этапа с одним аргументом вместо двух
- **THEN** `script check` сообщает о нехватке аргумента до исполнения

#### Scenario: Некорректная спецификация
- **WHEN** скрипт передаёт спецификацию с неизвестным именем этапа или
  некорректным параметром
- **THEN** при фатальном режиме (по умолчанию) исполнение завершается
  диагностикой, при не-фатальном скрипт получает ошибочный результат и
  ветвится сам
