# Spec Delta

## Purpose

Дополняет capability `repl-control` (baseline — change `init-current-system`):
программная установка паттерна drum-lane через единый фасад контроля, команды
REPL домена `drum` (включая создание drum-дорожки из REPL) и автодополнение;
та же операция доступна скриптовому фасаду.

## ADDED Requirements

### Requirement: Установка паттерна lane через фасад
Фасад контроля SHALL предоставлять операцию установки паттерна одного lane'а
drum-дорожки строкой-нотацией (адресация дорожки по имени, lane'а — по
индексу/GM-номеру/имени, нотация — по правилам capability drum-engine).
Применение SHALL быть немедленным; результат — подтверждение с именем
дорожки, lane'ом и итоговым числом активных шагов либо человекочитаемая
ошибка (несуществующая дорожка, дорожка не drum, неизвестный lane,
некорректная нотация).

#### Scenario: Установка из REPL
- **WHEN** пользователь выполняет `drum pattern "Drums" kick x..x|x..x|....|....`
- **THEN** паттерн lane'а kick дорожки «Drums» применён немедленно, транспорт
  играет заданный бит

#### Scenario: Ошибка нотации
- **WHEN** пользователь задаёт нотацию с некорректным символом
- **THEN** фасад возвращает ошибку с текстом проблемы, паттерн не меняется

#### Scenario: Не drum-дорожка
- **WHEN** пользователь задаёт drum-паттерн melodic-дорожке
- **THEN** фасад возвращает ошибку, состояние дорожки не меняется

### Requirement: Создание drum-дорожки из REPL
REPL SHALL поддерживать создание drum-дорожки командой `drum add [name]`
(без имени — автоимя счётчика; пустое/дубликат — ошибка). Канал и порт
назначаются по общим правилам сессии (drum — канал 9).

#### Scenario: Создание с автоименем
- **WHEN** пользователь выполняет `drum add`
- **THEN** создаётся drum-дорожка с автоименем, привязанная к свободному
  порту, статус-бар и `tracks` показывают её

#### Scenario: Дубликат имени
- **WHEN** пользователь выполняет `drum add "Kick"` при существующей дорожке
  «Kick»
- **THEN** создание отвергается с сообщением об ошибке

### Requirement: REPL-команда установки паттерна
REPL SHALL поддерживать команду `drum pattern <track> <lane> [<notation…>]`:
имена дорожек с пробелами — в кавычках; нотация может содержать пробелы и
`|` без кавычек; вызов с двумя аргументами (без нотации) SHALL очищать lane
(эквивалент пустой нотации). Ошибка разбора/установки выводится с кодом
возврата 1 и не прерывает цикл REPL.

#### Scenario: Евклид из REPL
- **WHEN** пользователь выполняет `drum pattern Drums shaker (3,8)`
- **THEN** lane'у shaker установлен евклидов ритм: три удара на бар
  (для `(3,8)` на сетке 16 — шаги 0, 6, 12)

#### Scenario: Очистка lane из REPL
- **WHEN** пользователь выполняет `drum pattern Drums kick` (без нотации)
- **THEN** все ячейки lane'а kick становятся выкл, остальные lane'ы не меняются

### Requirement: Автодополнение drum-команд
Автодополнение SHALL подсказывать действия домена `drum`, имена дорожек после
`drum pattern` и имена lane'ов следующим токеном.

#### Scenario: Подсказка lane'ов
- **WHEN** пользователь набирает `drum pattern Drums ki<TAB>`
- **THEN** предлагается имя lane'а `Kick`

### Requirement: Скриптовый фасад установки паттерна
Скриптовый фасад SHALL предоставлять ту же операцию установки паттерна lane'а
(арность и семантика — как у фасада контроля); вызов с неверной арностью
SHALL отвергаться статической валидацией скрипта до исполнения, ошибка
движка при исполнении — завершать скрипт с диагностикой (fatal по умолчанию).

#### Scenario: Скрипт задаёт бит
- **WHEN** скрипт создаёт drum-дорожку и задаёт kick/snare/hat паттерны
- **THEN** `script check` проходит без диагностик, `script run` применяет
  паттерны, транспорт играет заданный бит

#### Scenario: Неверная арность
- **WHEN** скрипт вызывает установку паттерна с двумя аргументами вместо трёх
- **THEN** `script check` сообщает о нехватке аргумента до исполнения
