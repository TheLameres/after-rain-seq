# Spec Delta

## Purpose

Дополняет capability `mutation` (baseline — change `init-current-system`):
ручная правка паттерна drum-lane извне (REPL/скрипт) входит в линейную
историю версий наравне с шагами мутации.

## ADDED Requirements

### Requirement: Регистрация drum-дорожки при создании
Drum-дорожка, созданная во время работы приложения (из REPL или скрипта),
SHALL регистрироваться в механизме истории версий в момент создания, если
механизм активен (мутация включена в конфигурации). Ведение истории SHALL
быть доступно такой дорожке с первой правки — без рестарта приложения.

#### Scenario: Создал → задал → undo
- **WHEN** пользователь создаёт drum-дорожку из REPL (`drum add`), задаёт
  lane'у паттерн и выполняет `undo`
- **THEN** lane возвращается к стартовому (пустому) биту, отказ «not mutable»
  не возникает

#### Scenario: Мутация выключена в конфиге
- **WHEN** механизм мутации отключён в конфигурации и пользователь задаёт
  паттерн lane'а
- **THEN** паттерн применяется к звуку, запись версии не выполняется,
  подтверждение это отмечает

### Requirement: Ручная правка паттерна как версия
Установка паттерна lane'а drum-дорожки из REPL или скрипта SHALL записываться
в линейную историю версий дорожки как новая версия (снимок состояния после
правки; состояние до правки уже хранится предыдущей версией). Повторная
установка идентичного паттерна SHALL НЕ создавать дубликат версии. Счётчик
мутаций дорожки SHALL синхронно увеличиться до номера новой версии. Undo и
recall после ручной правки SHALL работать так же, как после шага мутации.

#### Scenario: Undo после ручной правки
- **WHEN** пользователь устанавливает lane'у новый паттерн и выполняет `undo`
- **THEN** lane звучит как до правки, счётчик мутаций возвращается на
  предыдущую версию

#### Scenario: Повтор той же правки
- **WHEN** пользователь повторно устанавливает lane'у тот же паттерн
- **THEN** новая версия в истории не создаётся, состояние дорожки не меняется

#### Scenario: Recall на версию до правки
- **WHEN** после ручной правки пользователь выполняет `recall` на версию 0
- **THEN** восстанавливается корневой бит, последующие версии остаются в
  истории до следующей правки/мутации

#### Scenario: Мутация после ручной правки
- **WHEN** после ручной правки пользователь делает `evolve` этой дорожки
- **THEN** шаг дрейфа применяется к установленному вручную паттерну, новая
  версия добавляется поверх (будущие версии отрезаются по общим правилам)

### Requirement: Правка дорожки вне истории
Установка паттерна на drum-дорожку, не зарегистрированную в механизме
истории (возможно только при отключённой мутации или недоступном механизме),
SHALL применять паттерн к звуку и сообщать, что версия не записана; отказом
такая правка не является.

#### Scenario: Дорожка вне истории
- **WHEN** паттерн устанавливается drum-дорожке без регистрации в истории
- **THEN** паттерн применён и звучит, в подтверждении отмечено отсутствие
  записи версии
