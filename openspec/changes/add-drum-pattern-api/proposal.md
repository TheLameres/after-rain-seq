# Proposal: add-drum-pattern-api

## Why

Drum-дорожку сегодня можно создать только вне REPL: пад-гридом Push 2 (NEW)
или скриптом (`session.add_drum`) — REPL-команды создания нет. Задать ритм
извне нельзя вовсе: ячейки lane'ов редактируются только пад-гридом Push 2,
мутацией (`DrumTrack._apply_mutation`, `FloatingEuclidean`) и откатом
(undo/recall). Скрипты и REPL (удобный путь по SSH без железа) не могут
воспроизвести конкретный бит — а это базовая потребность и для примеров, и для
воспроизводимых сценариев. Нужен программный вход в drum-сетку: строка-нотация
(литеральные ячейки + евклидов ритм как гражданин нотации), проводимая через
единственный фасад `EngineControl`, с записью правки в историю версий, чтобы
undo/recall оставались согласованными после ручных правок.

## What Changes

- Новый компилятор строки-нотации в ячейки lane-сетки (0/1/2): чистый модуль
  в слое `session.model`, рядом с `DrumLane`/`euclidean.py`, без зависимостей
  вверх. Евклид-группа `(p,s[,offset])` — p ударов на весь бар: сегменты
  растягиваются на сетку через переиспользование `PEuclideanCached`.
- Новый метод фасада `EngineControl.set_drum_pattern(name, lane, pattern)` +
  реализация в `AppEngineControl` (валидация дорожки/lane, компиляция,
  применение, запись версии).
- REPL-команды домена `drum`: `drum add [name]` (закрывает найденный пробел —
  сейчас REPL вообще не может создать drum-дорожку) и
  `drum pattern <track> <lane> [<notation…>]` (без нотации — очистка lane'а);
  автодополнение дорожек и lane-имён.
- Обёртка `ScriptSession.set_drum_pattern(...)`; валидатор подхватывает метод
  автоматически (рефлексия), задача фиксирует это тестом.
- Ручная установка паттерна записывается в `VersionHistory` как новая версия:
  undo/recall работают после REPL/скриптовых правок так же, как после мутаций.
  Для этого drum-дорожка, созданная в рантайме, регистрируется в механизме
  истории при создании (сегодня `MutationEngine` регистрирует только дорожки,
  существовавшие на старте).
- Исполняемый пример `examples/drum_dub.py` для ScriptRunner (kick/snare/hat
  литералами, евклид на перкуссии, запуск транспорта).
- Раздел README «Drum-паттерны из REPL и скриптов»: синтаксис нотации, примеры.

Из SCOPE осознанно НЕ входит: оператор вероятности `?` и оператор
альтернативы `a|b` в нотации (решение в design.md — отложены), вложенность и
относительные длительности Strudel (`[]`, `<>`, `*`, `/`, `@`, `!`, polyrhythm),
изменение числа шагов сетки из нотации, редактирование mute lane'а.

## Capabilities

### Modified Capabilities

- `drum-engine`: добавляются требования к нотации паттерна lane — грамматика
  (литеральные ячейки либо одна евклид-группа на весь бар), маппинг в ячейки
  0/1/2, правила длины относительно сетки дорожки.
- `repl-control`: добавляются требования к методу фасада `set_drum_pattern`,
  REPL-командам домена `drum` (включая создание drum-дорожки из REPL) и
  автодополнению; скриптовый фасад получает ту же операцию.
- `mutation`: добавляется требование — drum-дорожка, созданная в рантайме,
  регистрируется в механизме истории при создании; ручная правка паттерна
  lane (из REPL или скрипта) записывается в линейную историю версий как новая
  версия (без дубликатов при повторе того же паттерна); undo/recall возвращают
  прежний бит.

Базовые спеки этих capabilities описаны change'ом `init-current-system` (пока
не синхронизирован в `openspec/specs/`); дельты здесь написаны как `ADDED`
относительно пустых main-спек, требования не пересекаются с baseline по именам
и после синхронизации обоих change'ов сходятся в единые спеки без конфликтов.

## Impact

- Код: `src/session/model/` (новый компилятор, `DrumTrack.resolve_lane`,
  публичная GM-карта), `src/session/mutation/mutation_engine.py` (запись
  версии), `src/repl/engine_control.py` + `src/app/engine_control.py` (фасад
  и регистрация drum-дорожки в механизме истории при создании),
  `src/repl/parser.py`/`executor.py`/`completer.py` + `src/main.py` (провайдер
  lane-имён), `src/scripting/script_session.py`, `examples/drum_dub.py`,
  `README.md`.
- Тесты: новые unit-тесты компилятора, фасада, обёртки, интеграции с историей;
  тест примера по образцу canonical-фикстуры `tests/test_scripting_runner.py`.
- Зависимости: без изменений. База линтеров (ruff 50 / black 11 / mypy 20,
  пре-существующие) не должна вырасти.
