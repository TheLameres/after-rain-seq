# Spec Delta

## Purpose

MIDI-порты и CC-автоматизация: логические лейблы вместо имён устройств,
обнаружение и hot-plug, перенаправление в рантайме, резолвинг логических
имён CC в номера и троттлинг автоматизации.

## ADDED Requirements

### Requirement: Логические лейблы портов
Порты SHALL конфигурироваться логическим лейблом (label) с правилами
поиска: match — регистронезависимая подстрока имени системного порта,
serial — дизамбигуация по серийнику; дорожки ссылаются на лейблы.

#### Scenario: Замена железа без правки сессии
- **WHEN** новое устройство совпадает по match с существующим лейблом
- **THEN** дорожки этого лейбла начинают звучать в новое устройство без правки сессии

### Requirement: Статусы портов
Каждый лейбл SHALL иметь статус: connected (одно совпадение),
disconnected (не найден), ambiguous (несколько совпадений и serial не
разрешил — с явным списком кандидатов), error.

#### Scenario: Неоднозначный match
- **WHEN** два системных порта совпадают по match без serial
- **THEN** лейбл получает статус ambiguous со списком кандидатов и никогда не угадывает

### Requirement: Hot-plug
Порты SHALL опрашиваться периодически (~2 с): подключённое устройство
оживляет дорожки лейбла; отключённое получает all_notes_off и молчит, сессия
продолжает работать.

#### Scenario: Устройство подключено после старта
- **WHEN** устройство, совпадающее с лейблом, подключается во время игры
- **THEN** дорожки лейбла оживают на ближайшем опросе без рестарта

### Requirement: Перенаправление порта в рантайме
Команда перенаправления (`ports switch`) SHALL менять целевое устройство
лейбла на лету: заявка применяется на ближайшем опросе, старый порт глушится
all_notes_off, serial сбрасывается, конфиг не переписывается.

#### Scenario: Switch на другое устройство
- **WHEN** пользователь выполняет `ports switch main "USB MIDI B"`
- **THEN** лейбл main перенаправляется на новом опросе, старый порт замолкает с all_notes_off

### Requirement: Маршрутизация дорожек
Дорожки SHALL подключаться и отключаться от портов-лейблов в рантайме
(route/unroute): переключение глушит старый порт, отключение — тишина при
живой сессии; движок дорожки создаётся автоматически при отсутствии.

#### Scenario: Unroute дорожки
- **WHEN** пользователь отвязывает дорожку от порта
- **THEN** дорожка молчит, сессия и её настройки продолжают жить

### Requirement: CC-маппинг по логическим именам
CC-автоматизация SHALL адресоваться по логическим именам параметров
(filter, reverb, …) с резолвингом: переопределение порта → глобальный default →
ошибка при загрузке конфига; поддерживаются инверсия и диапазон значений;
отдельный порт может исключить автоматизацию целиком.

#### Scenario: Переопределение CC на порту
- **WHEN** порт переопределяет `filter` на другой номер CC
- **THEN** генераторы этого порта шлют переопределённый CC, остальные порты — default

### Requirement: Троттлинг CC
Автоматизация SHALL проходить троттлинг не чаще 30 Гц по ключу
(порт, канал, CC); последний результат серии SHALL доставляться при сбросе
(all_notes_off, граница такта).

#### Scenario: Быстрая серия CC
- **WHEN** генератор шлёт серию значений одного CC чаще 30 Гц
- **THEN** на порт уходят не более 30 сообщений в секунду по этому ключу

### Requirement: Конфигурация с валидацией
Все секции конфигурации (логирование, клок, порты, CC-маппинг, drum,
мутация, устройства, UI) SHALL валидироваться при загрузке; невалидный конфиг
— понятное сообщение и отказ старта движка. Первый запуск создаёт конфиг с
дефолтами рядом с файлом запуска.

#### Scenario: Ошибка в конфиге
- **WHEN** в конфиге задано неизвестное имя CC-параметра
- **THEN** загрузка завершается понятным сообщением об ошибке, движок не стартует
