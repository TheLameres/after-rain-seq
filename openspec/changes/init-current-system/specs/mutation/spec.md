# Spec Delta

## Purpose

Ручная мутация и линейная история версий: явный шаг мутации (NEW / evolve),
применение только на границе цикла дорожки, стек снимков паттерна с undo/recall
и LED-индикацией pending на pads Push 2.

## ADDED Requirements

### Requirement: Мутация только по явному действию
Паттерны дорожек SHALL оставаться неизменными, пока пользователь не попросит
шаг мутации явно (кнопка NEW на Push 2 или команда `evolve` в REPL); темп и
время на паттерны не влияют.

#### Scenario: Нет изменений без действия
- **WHEN** транспорт играет долго и пользователь не нажимает NEW / evolve
- **THEN** паттерны всех дорожек не меняются

### Requirement: NEW / evolve на выбранную и все дорожки
Действие NEW SHALL мутировать выбранную дорожку, Shift+NEW и `evolve` без
аргумента — все дорожки, `evolve <track>` — указанную.

#### Scenario: Evolve одной дорожки
- **WHEN** пользователь выполняет `evolve "Stab 1"`
- **THEN** ожидание мутации ставится только на «Stab 1», остальные не тронуты

### Requirement: Применение на границе цикла
Нажатие NEW SHALL только ставить pending-флаг; сама мутация SHALL применяться
на ближайшей границе цикла дорожки (мелодическая — длина паттерна в битах,
drum — сетка/4), где снимается снимок головы, выполняется шаг дрейфа и
создаётся новая версия, после чего паттерн перегенерируется.

#### Scenario: Pending до границы цикла
- **WHEN** пользователь нажимает NEW в середине цикла дорожки
- **THEN** паттерн звучит неизменно, до границы цикла на дисплее виден флаг PENDING

#### Scenario: Два NEW в одном цикле
- **WHEN** пользователь нажимает NEW дважды до границы цикла
- **THEN** на границе создаётся ровно одна новая версия

### Requirement: Pending переживает остановку
Pending-флаг SHALL сохраняться при stop и применяться на первой границе цикла
после запуска транспорта; stop не отменяет и не применяет мутацию.

#### Scenario: Stop/start с pending
- **WHEN** при pending транспорт останавливается и запускается заново
- **THEN** мутация применяется на первой границе цикла после старта, не в момент старта

### Requirement: Линейная история версий
Каждая дорожка SHALL вести линейную историю версий (снимки: ступени/лейны,
пульсы, состояние дрейфа, параметры): мутация добавляет версию в стек,
восстановление (recall) переводит курсор на выбранную версию, мутация после
undo/recall отрезает будущие версии.

#### Scenario: Undo отрезает будущее
- **WHEN** после undo пользователь делает ещё один шаг мутации
- **THEN** версии после курсора удаляются, новая версия добавляется поверх

### Requirement: Лимит истории 256
История SHALL хранить до 256 версий на дорожку; при переполнении вытесняется
самая старая версия, корень (версия 0) не вытесняется никогда.

#### Scenario: Переполнение истории
- **WHEN** дорожка достигает 257-й версии
- **THEN** удаляется вторая (первая после корня), корень остаётся

### Requirement: Undo и recall
Система SHALL откатывать выбранную дорожку на одну версию назад (undo) и
переходить на любую сохранённую версию (recall); undo на корне и recall на
несуществующий номер SHALL отклоняться без изменения состояния.

#### Scenario: Undo на корне
- **WHEN** пользователь делает undo, когда дорожка стоит на корне
- **THEN** система сообщает об отказе, состояние не меняется

### Requirement: Счётчик мутаций
Счётчик мутаций дорожки SHALL равняться номеру текущей версии от корня и
возвращаться в 0 при откате к корню.

#### Scenario: Откат уменьшает счётчик
- **WHEN** дорожка с 3 мутациями откатывается на одну версию
- **THEN** счётчик показывает 2

### Requirement: Смена профиля и правки degrees сбрасывают историю
Изменение ступеней прогрессии или смена профиля дорожки SHALL сбрасывать
историю версий: счётчик и курсор обнуляются, новая версия 0 создаётся из
текущего состояния.

#### Scenario: Set base после мутаций
- **WHEN** пользователь меняет degrees дорожки с накопленной историей
- **THEN** история версий обнуляется, текущий паттерн становится корнем

### Requirement: LED-индикация падов версий
Сетка падов Push 2 SHALL показывать версии по колонкам (колонка = дорожка,
строка = версия, текущая подсвечена цветом дорожки); дорожка с pending мигает
на паде текущей версии (программное мигание по каналам LED).

#### Scenario: Pending мигает
- **WHEN** у дорожки стоит pending-мутация
- **THEN** пад её текущей версии мигает с периодом ~0.5 с, остальные горят статично

### Requirement: Переход по паду
Нажатие пада на экране версий SHALL переводить выбранную дорожку на эту
версию (recall); навигация Up/Down — по версиям, Shift+Up/Down — по страницам
версий, Left/Right — по дорожкам.

#### Scenario: Recall через пад
- **WHEN** пользователь нажимает пад на строке версии 2 колонки дорожки
- **THEN** дорожка переходит на версию 2, паттерн восстанавливается из снимка
