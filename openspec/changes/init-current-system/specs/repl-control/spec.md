# Spec Delta

## Purpose

Терминальный интерфейс и фасад управления движком: REPL на prompt_toolkit
для мониторинга и контроля (удобно по SSH), доступ к движку — только через
EngineControl и атомарные снапшоты состояния.

## ADDED Requirements

### Requirement: REPL с живым статус-баром
Приложение SHALL запускать строчный REPL (prompt_toolkit) по флагу `--repl`:
статус-бар обновляется ~2 Гц (bpm, клок с pending/error, root/scale, дорожки,
мутации, порты, Link-пиры), есть история команд и автодополнение.

#### Scenario: Статус-бар во время игры
- **WHEN** транспорт играет и пользователь стоит в пустом приглашении
- **THEN** статус-бар обновляется приблизительно дважды в секунду

### Requirement: Команды REPL
REPL SHALL поддерживать команды: status, start/stop, bpm, clock [source …],
ports [scan|switch …], tracks, track add|show|route|unroute|channel|delete,
root, scale, evolve, undo, recall, history, logs [N], help, exit; EOF и
Ctrl+D завершают приложение.

#### Scenario: Переключение клока из REPL
- **WHEN** пользователь вводит `clock source midi`
- **THEN** заявка на смену источника подаётся движку, статус-бар показывает pending

### Requirement: Подтверждение деструктивных действий
Деструктивные команды (stop, track delete) SHALL требовать подтверждения
y/N, с возможностью пропустить подтверждение флагом команды.

#### Scenario: Удаление дорожки с подтверждением
- **WHEN** пользователь вводит `track delete "Pad 1"`
- **THEN** запрашивается подтверждение; без подтверждения ничего не удаляется

### Requirement: Единственный фасад движка
REPL и UI-контроллер SHALL обращаться к движку только через единый интерфейс
контроля (EngineControl); прямой доступ к внутренностям приложения им
запрещён.

#### Scenario: Новая команда через фасад
- **WHEN** добавляется новая управляющая команда
- **THEN** и REPL, и UI-контроллер используют один и тот же метод фасада

### Requirement: Атомарный снапшот состояния
Снапшот состояния (StatusSnapshot) SHALL собираться в главном цикле и
заменяться атомарно; REPL SHALL читать только снапшот, не живой движок.

#### Scenario: Чтение во время игры
- **WHEN** REPL читает статус во время активной работы движка
- **THEN** REPL получает консистентный снапшот без блокировок движка

### Requirement: История и логи
История команд SHALL сохраняться в файл рядом с конфигом (с ограничением
объёма); последние записи журнала приложения SHALL быть доступны командой
logs.

#### Scenario: Просмотр логов
- **WHEN** пользователь вводит `logs 20`
- **THEN** показываются последние 20 записей журнала приложения

### Requirement: Рантайм-only изменения
Изменения, сделанные через REPL (клок, порты, маршрутизация, параметры
дорожек), SHALL действовать только в памяти процесса и не переписывать
конфигурационный файл.

#### Scenario: Конфиг не трогается
- **WHEN** пользователь меняет BPM и маршрутизацию дорожек из REPL
- **THEN** конфигурационный файл остаётся неизменным до рестарта

### Requirement: Headless-запуск
Без флага `--repl` приложение SHALL запускаться headless без терминального
интерфейса и завершаться по сигналу с чистым shutdown (код 0).

#### Scenario: SIGTERM в headless
- **WHEN** headless-процесс получает SIGTERM
- **THEN** все выходы глушатся корректно (all_notes_off), процесс завершается с кодом 0
