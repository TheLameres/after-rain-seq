# Spec Delta

## Purpose

Дополняет capability `repl-control` (baseline — change `init-current-system`):
операции захвата вывода в SMF через единый фасад контроля, команды REPL
домена `capture` и автодополнение; те же операции доступны скриптовому
фасаду.

## ADDED Requirements

### Requirement: Операции захвата через фасад
Фасад контроля SHALL предоставлять операции: старт захвата (с явным путём
или без — автогенерация имени), стоп захвата (запись SMF-файла) и статус
захвата (активен/не активен, путь, счётчик накопленных событий). Состав
потока и файловая семантика — по capability capture-smf. Ошибки (захват
уже активен, стоп без захвата, файл существует, транспорт недоступен)
SHALL возвращаться как человекочитаемый результат ошибки без исключений.

#### Scenario: Старт и стоп из REPL
- **WHEN** пользователь выполняет `capture start`, играет несколько баров,
  затем `capture stop`
- **THEN** фасад сообщает путь созданного файла и число записанных
  note-событий

#### Scenario: Повторный старт
- **WHEN** пользователь выполняет `capture start` при активном захвате
- **THEN** фасад возвращает ошибку «capture already running», активный
  захват продолжается

#### Scenario: Статус
- **WHEN** пользователь выполняет `capture` (без аргументов) при активном
  захвате
- **THEN** выводится путь, BPM старта и текущее число накопленных событий;
  без активного захвата — «capture is not active» (не ошибка)

### Requirement: REPL-команды домена capture
REPL SHALL поддерживать команды: `capture` (статус), `capture start [path]`
(путь с пробелами — без кавычек или в кавычках, склеивается), `capture stop`.
Ошибка выполнения выводится с кодом возврата 1 и не прерывает цикл REPL.

#### Scenario: Явный путь с пробелами
- **WHEN** пользователь выполняет `capture start "My Takes/take 1.mid"`
- **THEN** захват пишется в указанный путь (при стопе)

#### Scenario: Ошибка стопа не роняет REPL
- **WHEN** пользователь выполняет `capture stop` без активного захвата
- **THEN** выводится ошибка с кодом 1, цикл REPL продолжается

### Requirement: Автодополнение capture-команд
Автодополнение SHALL подсказывать домен `capture` и его действия
`start`/`stop`.

#### Scenario: Подсказка действий
- **WHEN** пользователь набирает `capture st<TAB>`
- **THEN** предлагаются действия `start` (и `stop`)

### Requirement: Скриптовый фасад захвата
Скриптовый фасад SHALL предоставлять операции старта и останова захвата
(аргумент пути опционален; семантика — как у фасада контроля); вызов
с неверной арностью SHALL отвергаться статической валидацией скрипта
до исполнения, ошибка движка при исполнении — завершать скрипт
с диагностикой (fatal по умолчанию).

#### Scenario: Скрипт пишет файл
- **WHEN** скрипт запускает транспорт, выполняет `session.capture_start()`,
  и после паузы `session.capture_stop()`
- **THEN** `script check` проходит без диагностик, `script run` создаёт
  SMF-файл по автогенерированному пути

#### Scenario: Неверная арность
- **WHEN** скрипт вызывает `session.capture_start("a", "b")`
- **THEN** `script check` сообщает о лишнем аргументе до исполнения
