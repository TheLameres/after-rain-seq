# Spec Delta

## Purpose

Новая capability: запись вывода приложения в SMF (.mid) с реальными
таймингами — верификация бита без DAW. Состав потока задаёт доставка
транспорта; файл пишется по команде из REPL или скрипта.

## ADDED Requirements

### Requirement: Состав потока записи
Захват SHALL записывать только события note_on/note_off всех дорожек,
как их доставляет транспорт (реально отправленные в порты; отброшенные
из-за отсутствия порта не записываются). MIDI-канал SHALL сохраняться
как есть (drum — канал 9). События CONTROL_CHANGE и ALL_NOTES_OFF и
real-time клок SHALL NOT записываться.

#### Scenario: Drum-дорожка попадает в файл
- **WHEN** транспорт доставляет удары drum-дорожки (канал 9) во время захвата
- **THEN** все note_on/note_off с каналом 9 присутствуют в файле,
  CC-события в файле отсутствуют

#### Scenario: Событие без порта
- **WHEN** транспорт отбрасывает событие (порт не найден)
- **THEN** этого события в файле нет

### Requirement: Тайминг и формат файла
Каждое событие SHALL записываться с реальной позицией в битах: для ноты,
отложенной свингом, — момент фактической доставки. Файл SHALL быть SMF
type 0 с одним треком, разрешением 480 тиков на бит, метами track_name,
set_tempo (BPM на момент старта захвата) и time_signature 4/4; тактовая
сетка таймлайна SHALL сохраняться (позиция в битах от нуля таймлайна).
При совпадении абсолютного тика note_off и note_on note_off SHALL
записываться раньше note_on (порядок в файле не зависит от порядка
доставки) — перекрытие одинаковых нот в файле исключено. Сдвиг свингом,
равный длительности 16-го шага, — граничный случай: удар записывается на
точный граничный тик (остаётся на целочисленной тик-сетке).

#### Scenario: Свинг не сдвигает сетку файла
- **WHEN** установлен ненулевой свинг и транспорт доставляет note_on
  со сдвигом, меньшим длительности 16-го шага
- **THEN** позиция удара в файле лежит на своём 16-м шаге (позиция в
  сетке не меняется, слышимый сдвиг сохранён в тиках)

#### Scenario: note_off раньше note_on на одном тике
- **WHEN** два соседних 16-х удара одной ноты (гейт 0.25 бита = 1/16)
  дают note_off удара k и note_on удара k+1 на одном тике, причём в
  транспортном потоке note_on доставлен раньше note_off
- **THEN** в файле note_off записан раньше note_on — перекрытия
  одинаковых нот нет, в DAW нота не ретриггерится и не залипает

#### Scenario: Tempo-мета
- **WHEN** захват начат при BPM 120
- **THEN** в файле на тике 0 записан set_tempo для 120 BPM; смена BPM
  во время захвата в файле не отражается

### Requirement: Управление записью
Система SHALL поддерживать команды захвата: старт (с путём или без —
автогенерация), стоп (запись файла), статус. События SHALL накапливаться
в памяти во время захвата; файл SHALL создаваться только на стопе.
Старт захвата при остановленном транспорте SHALL быть разрешён
(записываются только доставленные события). Стоп без активного захвата
SHALL давать ошибку; повторный старт при активном захвате SHALL давать
ошибку. Захват SHALL управляться через единый фасад контроля.

#### Scenario: Старт при стоящем транспорте
- **WHEN** пользователь выполняет `capture start` до запуска транспорта
- **THEN** захват активен (статус это показывает); после запуска
  транспорта доставленные события накапливаются

#### Scenario: Стоп без активного захвата
- **WHEN** пользователь выполняет `capture stop` без активного захвата
- **THEN** команда возвращает ошибку, файл не создаётся

### Requirement: Файловая семантика
Без аргумента путь SHALL генерироваться как `captures/capture_YYYYmmdd_HHMMSS.mid`
(локальное время; каталог создаётся при необходимости); коллизия имени
внутри той же секунды SHALL разрешаться свободным суффиксом `_NN`.
Явный путь используется как указан. Перезапись существующего файла
SHALL быть запрещена: старт с существующим путём даёт ошибку; стоп
SHALL создавать файл эксклюзивно (появление файла между стартом и
стопом даёт ошибку, а не перезапись).

#### Scenario: Автогенерация имени
- **WHEN** пользователь выполняет `capture start` без аргумента
- **THEN** файл будет создан в каталоге `captures/` с именем по времени
  старта, каталог создан при отсутствии

#### Scenario: Перезапись запрещена
- **WHEN** пользователь выполняет `capture start exists.mid`, где
  `exists.mid` уже существует
- **THEN** команда возвращает ошибку, существующий файл не меняется

### Requirement: Верифицируемость файла
Записанный файл SHALL читаться стандартными средствами (mido) и
диагностическим спайком `spikes/spike_midi_dump.py`: структура (SMF type,
ticks_per_beat, tempo), позиции ударов на 16-й сетке, каналы и
velocity-полосы восстанавливаются из файла.

#### Scenario: Приёмка по эталону drum_dub
- **WHEN** в `--simulate --repl` выполнены `script run examples/drum_dub.py`,
  `capture start`, несколько баров, `capture stop`, затем
  `uv run python spikes/spike_midi_dump.py <файл> --drum-dub`
- **THEN** kick/snare/hat/shaker/conga отмечены OK: позиции на 16-й сетке,
  канал 9, velocity-полосы 90–100/120–127
