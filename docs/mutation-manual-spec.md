# Спецификация: ручная мутация и линейная история

Статус: **согласовано по Q1–Q4 и уточнениям (мигание pending, колонки по дорожкам с пагинацией, без freeze)**. Реализация не начата.

## 1. Что меняется

- **Автономной мутации нет.** Таймера (`next_mutation_beat`), `sync_mutate`
  и зависимости мутации от BPM больше нет. Изменение темпа паттерн не трогает.
- **Мутация только по явному действию:** кнопка `NEW` на Push 2 или команда
  `evolve` в REPL. Одно действие — одна мутация на дорожку.
- **`evolve` = мутировать.** Без аргумента — все дорожки, `evolve <track>` — одна.

## 2. Freeze

Freeze не нужен: мутация только ручная, и «заморозка» как понятие не имеет смысла.

- `RECORD` больше не означает freeze.
- `freeze` в REPL, `DrumTrack.freeze`, `MelodicTrack.freeze` и правило «mutate=0 — заморожено» (§4.3)
  удаляются.

## 3. Назначение кнопок (Q2)

| Ввод | Эффект |
|---|---|
| `NEW` (CC 87) | Шаг мутации на выбранной дорожке (текущий TRACK) |
| `SHIFT` + `NEW` | Шаг мутации на всех дорожках |
| REPL `evolve <track>` | То же, что `NEW` для указанной дорожки |
| REPL `evolve` | То же, что `SHIFT` + `NEW` |

Кнопка `NEW` резерв в маппинге, обработчика нет. Занимаем её.

## 4. Сетка версий на Push 2 (pad 36–99)

Сетка 8×8 показывает историю версий **по колонкам на дорожку**:

- **Колонка = дорожка.** Колонки идут в порядке дорожек сессии. Одна страница сетки
  вмещает 8 дорожек; при 9–16 дорожках сетка переключается по страницам (Left/Right
  на сетке или выделенные кнопки страниц).
- **Строка = версия.** Версия 0 (корень) сверху, каждая следующая версия ниже (стек
  растёт вниз). На одной колонке видно 8 версий. Версий больше 8 — вертикальная прокрутка
  по страницам (вверх/вниз), сверху индикатор «версии 9–16 из 40».
- **Текущая версия** подсвечена постоянным цветом трека.
- **Pending (ожидает мутации)** — **мигание** пада текущей версии дорожки
  (см. §4a). Обычная версия не мигает.
- **Нажатие пада** = переход на эту версию (`recall`). Колонка другой дорожки
  выбирает дорожку и переводит её на версию.
- Пады не используются для нот: обработчика pad notes в приложении нет.

Лимит истории 256 версий на дорожку (см. §6). Сетка 8×8 показывает до 8 версий на
странице, всего страниц — до 32 на колонку, навигация по страницам версий.

## 4b. Навигация (стрелки)

| Ввод | Эффект |
|---|---|
| `Left` / `Right` | Переключить активный трек (предыдущий / следующий). |
| `Shift` + `Left` / `Right` | Листать треки страницами по 8 (как сейчас в `_nav_left`/`_nav_right`). |
| `Up` / `Down` | Прокрутка версий активного трека на одну версию (вверх / вниз). |
| `Shift` + `Up` / `Down` | Листать версии страницами по 8. |

Что меняется относительно текущего кода:

- Сейчас на экранах дорожек `Up`/`Down` двигают курсор `selected` (`_move_cursor`).
  По новой схеме они двигают версии, а выбор трека остаётся за `Left`/`Right`.
- `Left`/`Right` и `Shift`+`Left`/`Right` сохраняют текущее поведение.
- Новый обработчик `Shift`+`Up`/`Down` не занят: проверено, что `Shift` сейчас
  используется только для страниц треков и Shift+Delete.

Остаётся открытым: на экранах не-дорожек (SCALE, SETUP, DEMO, PORTS) `Up`/`Down`
уже заняты своими функциями, поэтому схема относится только к экранам дорожек.

## 4a. Индикация pending (мигание)

- Дорожка с `pending = True` мигает: пад текущей версии переключается между цветом
  трека и тёмным (или яркостью) с периодом ~0.5 с.
- Мигание снимается в момент применения мутации (граница цикла, §5).
- Мигание показывает только дорожки, которые ждут; дорожки без ожидания статичны.
- На экране TRACK/TRACKS та же индикация: строка дорожки мигает флагом `PENDING`,
  соответствующим `screens.py:513` (`PENDING -> ...`).

Реализация мигания — отдельная задача: в проекте нет кода вывода LED падов, поэтому
нужно сначала подтвердить протокол Push 2 (SysEx/note-on с велосити палитры) и
решить, мигание на стороне устройства или программным таймером.

## 4c. MIDI clock и мигание (решения)

- **Clock отправляется из таймлайна.** В `hooked_dispatch` (application.py), на каждом
  `TICK` (1/480 бита): каждый 20-й тик — импульс 0xF8 (24 на бит). Старт/стоп/продолжить
  (0xFA / 0xFC / 0xFB) — по событиям транспорта. Отправка через `Push2Device.send_midi`.
- **Канал мигания pending = 14 (quarter, 1/4 такта).** Пад текущей версии дорожки:
  note-on, канал 14 (blinking). Сброс при применении мутации: канал 0.
- **Pending переживает stop.** Stop не сбрасывает `pending` и не применяет мутацию.
  Порядок при остановке и запуске:
  1. `Stop` (0xFC): `pending` остаётся, мигание продолжается, паттерн не меняется.
  2. `Start` (0xFA): транспорт работает, но мутация ещё не применена.
  3. Мутация применяется на **первой границе цикла дорожки после start**, а не
     в момент самого start (правило §3: изменения паттерна только на границе).
  4. Сразу после применения `pending = False`, канал мигания — 0.
  Stop = пауза, а не отмена. Если граница совпадает со start (старт ровно на границе),
  мутация применяется на этом же тике.
- **Undo на Push 2 — кнопка `UNDO` (CC 119).** Откат выбранной дорожки на одну версию
  (то же, что REPL `undo <track>`). В маппинге CC 119 помечен как резерв, обработчика нет.
  На корне — отказ (состояние не меняется).

## 5. Синхронизация циклов (Q4)

Граница цикла — свойство дорожки:

- **Melodic:** `pattern_length_for(ctx)` в битах.
- **Drum:** `steps / 4` битов (сетка из `steps` шагов на такт).

Механизм:

1. Каждая дорожка держит **ожидающую мутацию** (`pending`), не больше одной.
   Нажатие `NEW` / `evolve` ставит `pending = True` на дорожку (или на все).
2. Таймлайн вычисляет границу цикла дорожки. Когда бит достигает границы, движок:
   a. применяет ожидающую мутацию (снимок головы → мутация → новая версия),
   b. сбрасывает `pending = False` (мигание прекращается),
   c. генерирует новый паттерн с этой версией.
3. Два `NEW` в одном цикле дают одну версию.
4. Дорожки независимы: каждая применяет шаг на своей границе.
5. Все изменения паттерна — **только** на границе цикла.

Потоки: нажатие только ставит флаг через очередь команд; снимок и мутация выполняются
в потоке таймлайна на границе.

## 6. История

- **Линейная.** Версии стеком. Мутация после `undo` / `recall` отрезает будущее.
- **Версия** — полный снимок: ступени/лейны, `pulses`, `_current` у `NoteDrift`,
  параметры `ParamDrift`. Восстановление пишет в объекты дрейфа.
- **Лимит 256** на дорожку. При переполнении вытесняется самая старая версия,
  корень (версия 0) не вытесняется никогда.
- **Курсор.** Дорожка всегда стоит на одной версии. Мутация из курсора в середине
  истории отрезает будущее (Q2 предыдущей версии: «отрезание»).

## 7. Счётчик

`mutation_count` = номер текущей версии от корня (нетто). Брутто не показывается.

## 8. Ошибки

- `evolve <track>` на несуществующей или не мутируемой дорожке — `EngineResult.fail`.
- `undo` на корне — отказ, состояние не меняется.
- `recall` на несуществующий номер — отказ.

## 9. Что это меняет в плане

- §5.4 (журнал) заменяется историей версий.
- Таймер мутации (§3.3, §4.2) и `bpm` в `tick` удаляются. §4.11 (темп) в части
  мутации становится излишним.
- `freeze` (§4.3, `RECORD`) удаляется.
- Тесты «счётчик не обрезается на 64», «freeze сбрасывает журнал» переписываются.

## 10. Тесты

- Нет изменений паттерна за 10 000 тиков без `NEW` / `evolve`.
- `NEW` ставит `pending`, но паттерн меняется только на границе цикла дорожки.
- Два `NEW` в одном цикле дают одну версию.
- Дорожки с разной длиной цикла применяют свои шаги независимо.
- `SHIFT`+`NEW` меняет все дорожки, `NEW` — только выбранную.
- `undo` возвращает предыдущую версию; `undo` на корне — отказ.
- Мутация после `undo` отрезает будущие версии.
- Восстановление пишет в `NoteDrift`, `FloatingEuclidean`, `ParamDrift`: следующий
  шаг дрейфа идёт от восстановленного значения.
- Вытеснение: 257-я версия удаляет вторую, корень остаётся.
- Пад N (36+) = переход на версию N; сетка показывает последние 64 при переполнении.
